# Integrations and security

Implementation note: REST enforces loopback peers, approved Host/browser origins and a local per-process 300/minute rate limit. Local clients can choose `X-Mock-Persona`; this is explicitly not authentication. MCP has a fixed operator-configured persona and no approval tool. Webhooks start disabled until an operator supplies a secret, never accept a persona, and require explicit queue processing via API/CLI/UI. Identical signed duplicates acknowledge idempotently; changed payloads conflict and stale duplicates fail timestamp checks. Retryable failures have at most three attempts with 2/4-second backoff and 60-second leases; business/policy failures immediately dead-letter. Failed/blocked idempotency traces remain original, so use a new key after changing a decision. Audit/trace/outbox redaction recognizes sensitive key names, not arbitrary free-text secrets: keep records synthetic. Audit is not tamper-proof against DB owners. The internal API dispatches only the local invoice-summary stub, with a 4KB cap and two attempts; its one-second synchronous processing budget is checked after execution and cannot interrupt arbitrary code. No arbitrary handler is exposed to model tools. See README for actual limitations and future real-auth requirements.

**Offline contract**: all SharePoint/M365/Azure examples are local simulators. Users should see `SIMULATION — NOT CONNECTED TO MICROSOFT TENANT`. Do not rely on unlicensed Power Automate environments.

Mock SharePoint: lists/invoices, list item read/write with row IDs, validation and authorization, SQLite persistence. Mock messaging: mailbox-like outbox to view notifications, no real sending. Mock Azure: labeled local persona (viewer, editor, reviewer, admin), static role policies not real authentication.

Optional future real integrations: outline delegated/application OAuth, Entra app registration, Graph scopes, token validation and tenant consent, throttling, connection references; behind disabled feature flag. Do not treat Azure CLI login as equivalent to backend production authentication.

Webhook security: `X-AgentFlow-Timestamp`, `X-AgentFlow-Event-Id`, `X-AgentFlow-Signature: sha256=<hex>` computed over `timestamp + '.' + raw_body`, HMAC SHA256; use hmac.compare_digest; max age 300 seconds, replay key persists; duplicate event id returns idempotent acknowledgement; invalid signature 401; old/replayed signature 401/409 as appropriate. Strict body size and input validation. Never include secret in responses/logs.

Protection: rate limits locally where viable; allowlisted internal URLs only; no arbitrary HTTP targets; sensitive data redaction; prompt-injection tests with docs such as 'ignore previous instructions'. Approvals before protected write actions. Synthetic records only.
